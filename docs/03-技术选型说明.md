# 03 · 技术选型说明

## 结论

**.NET 8 (LTS) + C# + WinForms 托盘应用**，NuGet 仅两个包（DPAPI 封装、GB2312 编码），单文件自包含发布。

## 候选对比

| 维度 | .NET 8 + WinForms（选定） | Python（requests + pystray） | Electron |
|---|---|---|---|
| 免安装交付 | ✅ 单 exe 自包含 69MB，零依赖 | ❌ 需打包 PyInstaller（体积相近）但目标机常被杀软误报 | ❌ 150MB+，还需 Node 运行时结构 |
| 开机到首检延迟 | ✅ 冷启动 <1s（实测启动→在线 116ms） | ⚠️ 解释器启动 1~3s + 依赖导入 | ❌ 进程模型重，秒级 |
| Windows API 亲和 | ✅ `NetworkChange`/`NotifyIcon`/`Registry`/DPAPI 全是一行调用 | ⚠️ 上述每一项都要 ctypes/第三方库拼装 | ⚠️ 全部经 Node 原生桥接 |
| 凭据安全 | ✅ `ProtectedData`（DPAPI）官方包，CurrentUser 作用域天然免管理员 | ⚠️ `win32crypt` 或 keyring（引入更多依赖） | ⚠️ safeStorage 在 Windows 底层仍是 DPAPI，但绑定 Chromium 数据目录 |
| 内存占用 | ✅ 托盘常驻 ~130MB（自包含单文件的内存解包所致，稳定不增长） | ✅ ~40MB | ❌ 200MB+ |
| HTTP 精细控制 | ✅ `HttpMessageHandler` 注入可测、禁代理/禁重定向/超时一把梭 | ✅ requests 足够 | ⚠️ 经 Net 栈间接 |
| 维护团队假设 | 校园工具的生命周期 = 学生在校年限，C#/WinForms 无需前端工具链 | — | — |

## 关键取舍记录

1. **HTTP 模拟 vs 内嵌 WebView2 自动填表**：逆向确认门户登录**无前端加密**（`js/login.js` 明文提交表单），HTTP 模拟体积小、速度快、可单元测试，选前者。若未来门户加验证码/加密，WebView2 是退化路径（见 docs/01 §3）。
2. **自包含 vs 依赖运行时发布**：目标用户是同学的分发场景，对方电脑大概率没有 .NET 8 运行时——69MB 单 exe 一次拷贝可用，优于"先装运行时"的摩擦。若在意体积可改 `--self-contained false`（~2MB，需运行时）。
3. **HKCU Run vs 计划任务（LogonTrigger）**：Run 键一行注册表、免管理员、用户可在任务管理器"启动应用"自主禁用；计划任务适合系统级/提权场景，本程序 asInvoker 完全不需要。
4. **Channel 触发队列 vs 直接 async**：网卡切换瞬间 `NetworkAddressChanged` 会连发多次事件，容量 1 的有界通道 + 单 Worker 把"合并触发、串行执行、不丢新触发"三个需求一次解决，且无锁无竞态（初版信号量方案存在丢失触发的竞态窗口，已重构替换）。
5. **GB2312 手工解码 vs 让 HttpClient 自动判码**：门户响应头 `charset=GB2312` 但个别接口裸文本；统一按字节读取 + 显式 GB2312 解码最稳，测试覆盖了中文表单值的编码往返。
