## 3. 登录表单结构（逆向自 `js/login.js`，已经实测捕获确认）

`loginSubmit()` 通过 `document.forms[0].xxx.value` 读写表单，最终 `$('form').submit()` 原生提交。实测捕获的登录页（2026-09-23）：

```html
<form action="login" method="post" >
  <input type="hidden" name="sourceurl" value="null"/>
  <input name="account"     type="text"     maxlength="25"/>
  <input name="password"    type="password" maxlength="25"/>
  <input type="radio" name="yys" id="n0" value=""        checked/>  <!-- 校园网免费，默认勾选 -->
  <input type="radio" name="yys" id="n1" value="unicom"/>
  <input type="radio" name="yys" id="n2" value="mobile"/>
  <input type="radio" name="yys" id="n3" value="telecom"/>
  <input type="checkbox" name="issave"/>
</form>
```

| 字段名 | 类型 | 说明 |
|---|---|---|
| `account` | text | 学号（JS 仅 `$.trim()`，无任何加密/哈希） |
| `password` | text | **明文提交**（无前端加密；**不允许包含 `;`**，否则 JS 拦截） |
| `yys` | radio | `""`（校园网免费，默认勾选）/ `unicom` / `mobile` / `telecom`。登录后账号形式为 `学号@unicom` 等 |
| `sourceurl` | hidden | 值字面量 `null`（原始来源 URL，实测客户端省略该字段亦可登录成功） |
| `checkcode` | text | 验证码，**条件字段**（当前捕获的登录页中不存在；推测多次失败后才由服务端输出） |
| `againLogin` | hidden | 值 `1`，仅"代拨开通后重登"场景由 JS 动态追加 |
| `issave` | checkbox | "记住密码"（仅前端 Cookie 行为，可忽略） |

**表单提交**：`POST /snnuportal/login`，`Content-Type: application/x-www-form-urlencoded`，页面编码 GB2312。

**关键结论：无前端加密，HttpClient 可直接模拟。** 若登录页出现 `checkcode` 字段，自动登录将被阻断，需转人工（软件有对应提示分支）。

## 6. 安全性评估

1. **门户全程 HTTP 明文**（含密码）——门户自身设计如此，客户端无法改变传输层；本地侧我们用 DPAPI 保证静态存储安全，日志永不记录密码。
2. 密码含 `;` 会被门户拒绝（前端校验），客户端配置向导需前置校验并提示。
3. 服务端按源 IP 识别会话意味着：**同一出口 IP 的重复登录会顶替会话**（对应"已在别处登录"场景）。
4. 客户端不得实现 `binding2`（代拨开通）自动化——涉及计费变更。
